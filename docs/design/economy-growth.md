# 0.22 回合递增收入

用户反馈固定每轮5金不足以支持后期刷新和追星。基础奖励改为六档，普通对战和野怪回合均采用本轮档位：

| 结算回合 | 基础金币 |
|---|---:|
| 1–5 | 5 |
| 6–10 | 7 |
| 11–15 | 9 |
| 16–20 | 11 |
| 21–25 | 13 |
| 26–30 | 15 |

利息仍按结算前余额每10金加1、最多5金；对战胜利额外1金；连续结果每3回合加1、最多3金。对战先更新连胜/连败，再计算本轮奖励。野怪不改变连续结果，不发对战胜利奖金，保留原有连续奖励。当轮淘汰不再发金币，重复结算、恢复已结束回合或进入下一轮不会重复发钱。玩家和全部AI共用同一规则。

后期基础奖励最多比原先多10金，相当于每轮额外5次刷新预算。第26回合起，在利息和战绩奖励全部达到上限时可得24金；仍需招募同名棋子合成，高星棋子没有改成直接出售。

`src/engine/economy.ts`集中定义档位、分项和总收入。指挥官面板直接显示本轮基础金额与下次增长点；指南说明递增规则。本局战报继续保存实际结算金额，不用新公式重算旧收益。

## 存档

规则singleplayer-0.22 / schema21。schema20只更新元信息，保留已有金币、阵容、商店、历史和回放。尚未结算的回合采用新收入；已结算的回合不追补差额，不需要重新开局。战斗版本保持metamorph，经济调整不改变历史战斗回放。

## 必要验证

- 13项经济测试覆盖全部30轮档位、封顶、利息边界、先更新连胜、8名玩家同规则、连败、淘汰、野怪、结算幂等、下一轮不重复奖励，以及旧准备/战斗/结算/终局四阶段迁移。
- 相关引擎8项、存档9项、单局流程5项、上版迁移4项通过，合计39项；上版迁移文件中11项无关战斗用例未运行，没有跑全量测试。
- TypeScript检查、Vite构建通过。浏览器中当前第18回合显示“本轮基础奖励+11金；第21回合增至+13金”，见[截图](../preview-income-growth.jpg)。

## 同种子经济采样

标准难度、种子137、7种构筑偏好，改动前后各7局。使用正常付费招募/刷新/经验和有限卡池，无额外金币或卡牌。每轮检查准备、结算和推进后的合法性；后期定义为第20回合起，收入均值包含淘汰回合的零收入。

| 后期指标 | 原固定收入 | 递增收入 |
|---|---:|---:|
| 采样回合数 | 23 | 43 |
| 每轮实际收入均值 | 4.83 | 11.98 |
| 每轮付费操作支出均值 | 9.61 | 14.14 |
| 每轮付费刷新次数均值 | 0 | 0.88 |
| 等级均值 | 8.30 | 9.42 |
| 上阵4/5费二星及以上数量均值 | 0 | 1.51 |
| 上阵三星数量均值 | 0.30 | 0.21 |

样本中资源已用于刷新、升级人口和高费二星；三星数量没有普遍增加，不据此宣称所有追星路线或整体平衡已完成。前后存活时长也发生变化，不能把这些均值视为严格独立因果效应或真人胜率。

[调整前](../analysis/economy-v022-before.json) / [调整后](../analysis/economy-v022-after.json)保留逐轮记录和源码哈希。复验脚本为`scripts/economy-survey.ts`，分别在调整前后工作树运行`npm run survey:economy -- before`和`npm run survey:economy -- after`；同一工作树运行两次不构成前后对照。
