# 战斗与操作音效

游戏加入原创程序合成音效，不使用原作录音，也不下载第三方音频文件。规则版本和存档格式不变，声音不参与战斗状态或随机数。

## 玩家操作

设置中提供“游戏音效”、0–100% 音量和“试听音效”。默认启用，音量 35%；第一次点击或键盘操作后才启用音频设备。刷新恢复音量与开关，旧显示设置自动补齐声音默认值。游戏存档与显示/声音偏好分开保存。

- 近战区分挥刃、重击、爪击，远程区分枪击、炮击、能量束、弓弦和灵能音。
- 治疗/保护与攻击施法使用不同声音；范围技能只按施法者发声，避免对每个目标叠加一遍。
- 招募、三合一、合成装备、部署、穿戴、领取奖励、开战及胜/负/平局有对应提示。
- 暂停停止正在播放的声音；静音和音量为零立即停止；后台始终静音，即使关闭“切到后台时暂停”。回到前台不会补播隐藏期间的音效。
- 演示和历史回放也有声音。演示战果停留期间暂停，不再自动重播下一轮。刷新到战斗中部时，只播放恢复位置之后的事件；刷新到旧战果不重复播放提示。

音量设置只改应用声音，不改变系统音量。没有新增背景音乐或配音。

## 实现

`src/audio/synthesis.ts` 生成短 PCM 波形：带包络的振荡音、滤波噪声、上行/下行音列。波形按音色缓存，噪声使用局部确定性序列，和游戏随机种子无关。

`src/audio/cues.ts` 从已有战斗快照建立播放事件表；普攻跟随各兵种动作的发射/挥击时点，施法跟随 cast 事件。持久游标与界面渲染分离，同一时间点不会因为重绘设置或面板重复发声。每次更新最多取四条新提示，技能优先，丢弃过期积压。

`src/audio/player.ts` 延迟创建 AudioContext，负责声像、总音量、压缩器、缓存和节点回收。战斗音效间隔至少 45ms，同时最多 12 个声音，避免四倍速堆叠。每次开始新回放、暂停、离开页面或检测到存档冲突时停止声音。设备或自动播放失败返回不可播放状态，游戏继续运行。

浏览器音频启用与音量控制参考 [MDN Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)，恢复行为参考 [AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume)。

## 验证

`npm run test:audio`：音频 7 项 + 偏好 9 项，共 16 项必要检查。覆盖：

- 全部 20 兵种具备音色，实际 PCM 为有限非静音信号，包络首尾归零、峰值受控，生成确定。
- 音轨不修改战斗结果，同帧不重复，静音消费游标，恢复/循环/跳时边界，范围施法去重。
- 设备首次交互前不创建、波形缓存、静音/后台停止、密度和声部限制、结束节点回收。
- 缺失设备和被拒绝的 resume 不向游戏抛出错误；旧设置迁移和非法音量回退。

TypeScript + Vite 构建通过。浏览器操作确认试听后显示“音效已就绪”，键盘调节音量、静音、刷新恢复和暂停演示有效；390px 弹窗未横向溢出，无控制台 error。另实际完成第 3 回合野怪战：自动结算并打开三选一奖励，领取合金刃后进入第 4 回合准备，生命 100、金币 23。

浏览器验证确认音频设备运行和交互流程；没有进行跨设备听感、耳机/扬声器矩阵或真人音效评审，不将信号检查等同于实际听感评价。
