# 战术难度、抱团布阵与轻量试算

2026-11-03。沿用单机自主规则。本次只改变决策和部署，不改变战斗数值、资源发放、卡池或存档结构。

## 三档决策

| 难度 | 阵容与升级 | 战术能力 |
|---|---|---|
| 休闲 | 简单选择单体强度，少量刷新，不购买经验，仍正常获得自然经验 | 固定分散站位 |
| 标准 | 攒息、追星、付费升级、组合搜索与羁绊 | 区分坦克、辅助、远程、刺杀的分散站位 |
| 挑战 | 标准经济接口，更宽的组合搜索与刷新预算 | 最多 3 个候选阵容 × 分散/抱团两种站位，对可见对手试算后择优 |

挑战 AI 只能读取准备时已经上阵的对手，或公开的本轮野怪。实际对手后续仍可能调整，因此试算不是保证胜利。选择标准按胜/平/负、双方剩余生命比例、耗时依次评分。预览中的装备分配只发生在副本，最终仅提交己方站位，随后使用原有合法装备流程；不购买未来商店、不修改对手、不提前生成奖励。

休闲的辅助布阵仍给玩家使用标准组合评估，不会因为新手难度而降低玩家“推荐布阵”的质量。难度说明已显示在指挥官面板。

## 玩家阵型选择

- “推荐布阵”：近战前排、治疗中段、远程分散后排。
- “抱团布阵”：将队伍集中在己方右侧，近战保护后排、辅助更容易覆盖队友。集中站位需要留意范围伤害。
- 两者都保持人口/占位约束，不出售棋子、不花金币、不改变装备。可以继续手动换位。战斗、演示和存档冲突期间禁用。

浏览器验证：原有 3 人阵容从分散改为盾兵 G6、马骑兵 H6、灵鱼 H8，仍为 100 生命/17 金/3 人口。390px 布局无横向溢出，两按钮高度 40px，均可操作。

## 轻量战斗试算

`simulate` 仍保留每个 tick 的完整动画快照，服务正式战斗与历史回放。新增 `simulateOutcome` 共用同一套 `runBattle`，只复制最终状态，用于 AI 候选比较。寻路、技能、伤害、状态处理和行动顺序完全一致；不引入近似战斗规则。空队伍、legacy/tactics、全部 20 种棋子、野怪阵容的最终生命、胜负、扣血与结束 tick 经定向测试比较一致。

84 局验证中，每回合的 AI 准备与八场实际战斗生成，在本机平均：休闲 6.79ms、标准 14.56ms、挑战 40.13ms；最大挑战回合 90.28ms。该数据来自 Node 运行，不等同于弱手机帧率或全浏览器性能保证。

复现：

```sh
npm run survey:balance -- difficulty-validation 137 307 809 1619
REDTIDES_SURVEY_POLICY=compact npm run survey:balance -- compact-response 137 307
```

标签对应的文件会被该次报告覆盖。采样代码在运行开始时记录源文件 SHA-256；`REDTIDES_SURVEY_POLICY` 支持 standard/compact/veteran，报告明确记录策略。此前 tactical-trial、tactical-holdout、difficulty-trial 是调试阶段记录，最终结论以上面 validation 为准。

## 必要模块检查

- tactical-ai：6 项，涵盖试算等价、两种阵型边界、对手/资源不被修改、确定性、准备阶段限制、各档购买经验规则。
- strategy：9 项，既有羁绊、部署、装备价值、辅助覆盖、卡池守恒与迁移。
- campaign：4 项完整对局、逐轮恢复与终局。
- engine：8 项，战斗、招募、经济、升星及占位核心回归。
- 合计 27 项通过，TypeScript 与 Vite 生产构建通过。未运行全量测试。浏览器控制台无 error。

上述数据对应 0.5 校准时点。0.6 的羁绊和终局野怪调整、同种子再采样见 [0.6 平衡调整](balance-06.md)；不要将历史报告当作当前版本胜率。
