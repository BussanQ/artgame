# 保留旧档并恢复当前局保存

0.78存档恢复后续，继续使用schema77与`support-actions`战斗规则。新增旧档保留、当前进度保存、旧档导出和失败重试入口；不新增兵种或改变战斗参数。

## 已确认的问题

不兼容主存档会使`SaveStore`进入只读状态，保护原始数据；当前临时新局可以继续操作，但自动保存始终返回`incompatible`。此前顶部通知只在已恢复、损坏或冲突时出现，不兼容状态只有页脚“本局暂不保存”，没有保留当前临时进度的入口。“载入最新存档”只刷新页面，不能解决不兼容问题，还可能丢掉尚未保存的操作。

## 玩家流程

- 不兼容或保存失败时，顶部同一行显示“本局未保存”（手机短文本为“未存”），展开可查看原因。
- 点击“保留旧档并保存本局”，先保存原始主档及当时的备份、损坏原文，再保存当前局。不会重新开始，不重抽禁用，不改变金币、棋子、装备、卡池、历史或播放位置。
- 保留失败时继续保留原主档和只读状态，可导出旧档，检查浏览器存储空间与权限后重试。普通保存失败提供“重试保存”。计算期间禁止发起写入恢复，导出仍可使用。
- 旧档保留后仍可通过顶部入口导出。下载文件为JSON，包含各原文及备份；未知格式作为字符串保存，不被执行，也不上传外部服务。发起下载的提示不等于浏览器已完成文件保存。
- 多窗口进度已变化时停止替换并暂停本窗口，仍使用原有“载入最新存档”流程。收起提示不会解除只读或冲突，也不会隐藏仍存在的未保存状态。

顶部状态局部刷新，保留展开状态与键盘焦点，不为更新存档提示重建战场或中断当前播放。延续原单行工具栏布局，不增加独立提示行。

## 数据保留与写入

`src/engine/persistence.ts`增加`protectAndSave()`、`exportOldSaves()`和两个只读状态属性。`red-tides.singleplayer.save.preserved`使用独立schema1保留数组，每项包含时间、原始主档字符串，以及可选的原始备份／损坏字符串。既有条目不被删除；相同主档重试不反复追加，缺失备份字段可补入，已经保存的字段不随后续轮转改变。

恢复先验证当前局，再核对主档与原读取值一致，追加／核对保留区，随后再检查主档并写入当前局，最后读回确认。保留失败、未知保留区格式、静默丢写或检测到多窗口更新时不解锁写入。保留区写入成功但主档写入失败时，可重复操作而不重复归档。该流程不声称提供跨标签页的数据库事务锁；它按可观察状态再次核对并拒绝已检测出的并发变化。

恢复动作本身不覆盖现有`backup`和`recovery`槽；其当时的内容也已进入保留条目，因此后续正常自动备份轮转不会丢失这些原文。普通保存增加读回验证，且存储恢复后未变的有效检查点可以清除先前错误状态。原保存格式、迁移链、显式重开流程及备份回退机制继续使用。
