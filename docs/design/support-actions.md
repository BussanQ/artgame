# 隐形期间的辅助行动

singleplayer-0.78，combatVersion `support-actions`，schema77。修复军医、长生鹿等辅助看不到敌人时停止施法的问题，同时让无可见目标期间的普攻冷却继续流逝。兵种、技能参数、美术与卡池不变。

## 复现与原因

此前行动循环先取得可见敌人；如果没有，只有维修机和无形的专门分支会继续行动，其他棋子直接跳过。军医的合法目标实际是伤员，长生鹿的合法目标是友军，两者的施法入口却被敌方隐形挡住，普通输出的攻击冷却也会冻结。

固定三对一场景使用现有装备提供起手能量，没有修改战斗属性或存档：二星盾兵、军医与长生鹿对三星幽灵机。幽灵机0.25秒开启无形，6.25秒显形。旧规则中军医一直满能量，长生鹿受击后也已满能量，但两者首次施法都等到6.25秒；长生鹿在6秒时仅剩398／1700生命。

本轮基于0.77未提交工作树冻结50代64种定义、技能呈现及原场景回放，再修改调度。不是用新代码回填旧基线，也不据这一个装备局面推断整体平衡。

## 新行动规则

`src/engine/support-actions.ts`处理没有可见敌人的空闲行动：

- 存活且空闲的棋子，其普攻冷却每步仍正常减少；包括眩晕期间，保留小数余量。等待不会产生普攻、敌方技能或向不可见敌人移动。
- 军医、长生鹿、维修机和无形可以以自身作为技能入口，再由各能力选择实际友军或自身目标。军医仍须有范围内的合法伤员；长生鹿仍按原范围与数量选择友军；维修机仍锁定最高攻击友军；无形仍遵守自身时长与冷却。
- 眩晕、沉默、魅惑、有效嘲讽、能量不足、个人冷却、刑傀、死亡和火种等限制保持。能量封锁仍只影响回复，不删除已经攒满的能量或施法资格。残魂军医保留既有救助存活友军的能力，自己不能被治疗。
- 正在引导、蓄势或完成技能的占用帧不会重复施法或多推进一次冷却。成功辅助施法只占用一次行动，不额外普攻；满血或无合法友军时不白白消耗能量。
- 友军隐形不妨碍治疗或防护；敌方隐形仍阻止定向攻击。只接入上述已有明确友军／自身目标语义的能力，其他能力继续遵守各自目标要求。

这是本项目的行动调度修复，没有新引入历史数值或声称取得新客户端规则。依据是既有[军医](medic.md)、[长生庇护](spirit-ward.md)、[灵蕴缝合](mending.md)与[无形](formless.md)的实际结算与已公开目标语义。

## 兼容与验证

[结构化验证记录](../analysis/support-actions-v078-validation.json)：支援26项与无形30项，共56项不同必要检查通过；加强维修机实际治疗、刑傀／嘲讽样例及真实庇护结束交互后定向4项通过。首次构建发现两处新增测试样例字段不完整，按实际类型补齐后TypeScript及179模块生产构建通过。没有运行全量测试、完整经营局或批量对战。

50代旧64种定义以及名称／说明／图像索引SHA保持，0.77原场景142帧回放SHA保持。schema76迁77：准备期升级，旧battle／result保留`formless`；原目录、卡池、商店、持有、历史和播放资料保持。迁移沿用原禁用，不重新抽取。

同一场景修复后两名辅助在1.25秒开始施法，敌方仍处于隐形；前6.25秒没有己方对幽灵机的普通攻击命中。军医最终实际治疗1120，长生鹿实际减伤89。模块结果从旧规则35.25秒己方失败变为新规则24秒己方胜利；这是特定局面中支援不再停手的证据，不能替代难度或平衡验收。回放与快算终态相同，输入不被修改，零秒战报不包含未来贡献。

浏览器仅观察到11.25秒片段，没有冒称看到终局。三秒回看显示军医治疗140、仍余3次治疗，长生鹿已保护两人；军医同时显示庇护+20护甲、+50%法术减伤，其数值为22甲和70%法术减伤。此时己方生命伤害为0，幽灵机无形仍生效，符合不能定向攻击隐形敌人的边界。
