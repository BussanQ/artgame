AI 决策、实际开战、战斗恢复、历史回放和兵种演示均通过 Web Worker 计算。界面显示计算状态，计算期间禁止购买、布阵、装备等对局修改；设置、说明、图鉴、侦察和重新开始仍可使用。实现采用 [Vite 的 Worker URL 入口](https://vite.dev/guide/features.html#web-workers)。

## 事务与失败边界

- `src/compute/job.ts` 定义开战、恢复、回放三类任务。工作副本完成全部 AI 准备和战果计算后，一次返回 Game 和 RoundResult，尚未扣血或发收入。
- 页面原始 Game 在计算中不改变。取消时终止 Worker，保持原准备状态；刷新仍恢复上一次已保存的阶段。
- 进行中的战斗恢复仅调用 resumeRound，不再次招募或刷新 AI。旧战斗版本由任务携带，历史回放使用报告保存的版本。
- 每次任务有独立序号和 Worker；取消、重新开始、离开页面、检测到其他标签更新都会使旧任务失效。迟到结果不能应用到新局。
- 创建、发送、执行、读取失败或 30 秒超时，会释放线程并提供重试。不会回退为主线程执行昂贵模拟，也不会提交部分计算状态。
- 取消战斗恢复后仍保留战斗存档，可用“恢复战斗”重试；取消历史回放替换会继续原有演示。取消已结算战报恢复后，玩家仍可选择奖励或推进下一回合。
- 结果接收后依旧由原回放流程播放胜败动画和音效，再执行原有自动结算/奖励流程；无需改动存档版本或平衡规则。

运行环境需要支持模块 Worker。不能启动时提供错误和重试，游戏不会静默跳过回合。Worker 计算期间仍可正常显示界面；快照传回、存档校验和绘制在主线程执行，因此不宣称主线程完全没有耗时操作。

## 避免生成无用快照

`resumeRound` 原先为所有存活玩家生成完整战斗帧，实际只展示玩家自己的对局。现在只为玩家保留完整帧，其他 AI 使用共用战斗循环的 simulateOutcome，保留末帧用于计算胜负与扣血。技能、行动顺序、随机状态和扣血公式不变。

以正常经济操作完成一局挑战难度（种子 617、购买偏好 4），在五个回合取样；每项预热一次、计时七次取中位数。参考版本对每位玩家调用完整模拟，当前版本调用 resumeRound；两者所有玩家战果逐项一致。

## 验证

- `tests/computation.test.ts` 8 项：三代规则的开战/恢复/回放逐帧一致、原 Game 不改写、结算只执行一次、AI 野怪/PvP 轻量战果与完整模拟一致、错误阶段、取消与迟到结果、超时/异常/消息错误后的回收与重试。
- 同时运行 campaign 4 项、balance-migration 5 项、persistence 9 项，共 26 项必要检查通过；未跑全量测试。
- TypeScript 与 Vite 生产构建通过，独立输出约 36KB 的 Worker 文件。
- 开发服务：第 4 回合实战自动结算至第 5 回合；第 5 回合开战后暂停并刷新，恢复为 0.0s 暂停状态，92 生命、30 金币、4 级；没有重复收入或重新准备 AI 的可见变化。
- 生产预览：正常招募盾兵、灵鱼、神射手，推荐布阵后成功开战并暂停于 0.3s，Worker 文件可正常加载。两种服务均无控制台 error。
- 取消/迟到消息等竞争边界由模块验证覆盖，未使用人为延迟伪装普通浏览器性能。

复现命令：`npm run test:computation`、`npm run audit:compute`、`npm run build`。真实低端设备的帧率和功耗仍未实测。
