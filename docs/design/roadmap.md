# 实施路线与验收

## M0：研究与工程基线（本次已完成）

交付 docs 资料目录、来源清单、规则摘记、美术入口、架构、差异清单；搭建 TypeScript + Vite；建立依赖锁文件。

验收：每项历史机制有出处；未知项不填伪造官方值；开发命令能启动，生产构建成功。

## M1：可玩单机垂直原型（本次已完成基础版）

8 个参与者、有限共享卡池、商店、经济、升星、部署、8 类简化羁绊、自动战斗、淘汰排名。最初用 12 种棋子和统一技能跑通循环；singleplayer-0.2 已替换为 12 种独立能力。当前优先级以 single-player-plan.md 为准，在线多人不属于本轮单机目标。

验收：招募→部署→战斗→结算→下一轮可操作；金钱/人口约束有效；卡池不凭空增减；战斗不破坏阵容；终局可重新开始。必要模块测试覆盖上述高风险逻辑。

## M2：规则完整性与数据恢复（下一优先级）

1. 确定要还原的历史版本。默认以 2019-04 的规则作为候选基线，但在棋子表核实前不宣称已锁定完整版本。
2. S03/S04图表已在0.21完成本轮字段提取，见historical-tables.md；继续核对同版本技能、属性冲突和未提供的商店概率。
3. 拆分能力系统：普攻、伤害类型、护盾、治疗、控制、召唤、变身、隐身、开场技能。
4. 按图鉴逐个实现棋子，加入装备/合成/掉落、野怪回合、完整羁绊梯度和异虫合成。
5. 本地存档已实现版本化 schema、校验、损坏回退与战斗恢复；当前历史回放使用参战阵容快照和确定性规则，尚无完整 command log。

0.8 已接入鬼狼召唤及临时战斗单位生命周期，保留四代旧战斗；牛魔已有短时施法变身外观，0.9 补入真人与须弥鲨，已可组成三召唤与傀儡阵容；猛禽/陆行者已在 0.15 补入，0.16 接入血鹰持续落地变身（bloodhawk-transformation.md）；其他历史技能仍待逐项核对；0.10 已接入四种异虫、进化和控制/自爆机制（见 insects.md）。实现与边界见 summons.md、bull-transformation.md、legions.md。

验收：每种技能有确定性场景；护盾和生命分离；未知配置可检查；原型配置和历史版本配置可切换，数据来源可追溯。

## M3：表现与可用性

将 main.ts 拆成视图组件与输入控制器，改为局部渲染；Web Worker 计算战斗；2D 美术资产与动画；弹道/技能/伤害浮字；完整键盘操作、焦点管理、静音与画质设置。图鉴增加排序、筛选、星级和羁绊详情。

验收：普通桌面与窄屏无关键遮挡；速度切换不改变结果；弱设备战斗播放不卡住操作；外部字体失败也能正常使用。

当前已实现 Canvas 美术和动画、显示/静音设置、键盘精确布阵及弹窗焦点管理；AI 准备和战斗/回放计算已迁入 Worker，见 background-computation.md。main.ts 仍是集成入口，并非已完成所有视图组件化；真实弱设备性能未实测。

## M4：8 人在线

共享规则包→权威服务器房间→WebSocket 协议→重连/超时/托管→匹配。客户端提交动作，不提交战斗胜负。房间保留命令序列与结果摘要以排查差异。

验收：8 客户端同房一致；重复/乱序命令不重复扣费；断线恢复；淘汰归还卡池；服务器不信任客户端资源或位置。

## 开发约束

- 用户未明确要求前不提交 git commit；未来提交信息用中文。
- 开发只执行必要模块测试和构建，不进行全量测试。
- 版本配置每次变更都更新差异文档；后续发布前按实际功能重写范围声明。
- 当前优先完善独立技能与装备，随后补完整棋子，再进行在线多人；避免同时扩大数据、美术和网络三个维度。

0.20已补火焰兵/投弹手、独立灼烧和沉默机制；当前49种棋子，历史名单39项对应、14项缺失，8项现有分类不同。下一步继续旧骑兵/装甲/傀儡及特种兵缺口；步兵2/3/6与历史2/4/6的迁移需要单独战斗版本，不能静默更改旧回放。

0.21已补摩托骑兵，当前50种；图表恢复揭示五月步兵减甲、七月棍奴职业变化、雷震子与童子被动定位等差异。下一步应继续缺失兵种并按选定历史切片对齐机制，不能用单机自主数值冒充统一历史版本。
